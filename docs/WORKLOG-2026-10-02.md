## Task 6 — Phase 5: about, contact, apply + enquiry ✅

`functions/api/enquiry.js` (ported), `functions/api/_ratelimit.js` (ported verbatim),
`functions/api/_time.js` (`melbourneDay`, extracted because aphelion's lives in
`admin/_traffic.js` alongside routing concerns), `functions/api/_alert.js`, `_apply`-side
`public/assets/form.js`, `/about`, `/contact`, `/apply`.

**Deviation — `_alert.js` is a rewrite, not a verbatim port.** aphelion's version delegates
its email leg to `_email.js`: a multi-provider sending stack with branded templates and a
send log that backs aphelion's Email tab. This site has no Email tab and no send history, so
vendoring a few hundred lines of machinery with no caller would be the worst of both worlds.
The port keeps Pushover and the Slack/Teams/Discord webhooks — the full `alertOwner()`
contract — and drops the email failsafe.

**Consequence, and it is a real one:** with `PUSHOVER_TOKEN`/`PUSHOVER_USER` unset there is
no alert channel at all, so `/api/enquiry` answers 503 (*correctly* — nothing stored and
nobody told) instead of accepting a trade application. `docs/SETUP-deploy.md` calls it out
as a required secret rather than an optional one.

**The application form writes a lead, never an account.** It sends `interest: "wholesale"`,
`business_slug: "repeater"`, `source: "apply:trade"`. Setting a credit limit or terms stays
an owner action in aphelion's Wholesale tab — a website form must not be able to set its own
credit limit. The ABN is a field the `leads` table has no column for, so it is folded into
`message` rather than altering aphelion's platform schema.

**Deviation — `novalidate` removed from both forms.** The spec asked for it, but a
`novalidate` form with JavaScript disabled posts straight to the endpoint and a validation
failure returns raw JSON to the visitor. Native validation is now left on, so both paths
behave. `tests/site.test.mjs` asserts it stays off.

**Gate:** contract suite green — both content types, honeypot, all four error paths, 429 on
the 6th hit, fail-open with no `rate_limits` table, and an assertion that no raw IP is ever
written (the hash is 16 hex chars, contains no dots).

## Task 7 — Phase 6: blog, sitemap, beacon ✅

`schema.sql` + `migrations/002_site_posts.sql`, `public/blog/index.html`,
`public/blog/article.html`, `functions/blog/[slug].js`, `functions/sitemap.xml.js`,
`functions/_middleware.js`, `functions/api/posts.js`, `tests/imports.test.mjs`.

**Addition not in the plan — `/api/posts`.** The plan's endpoint list had three; the home
teaser and `/blog` need a fourth, because hardcoding post cards into the markup would show
articles that don't exist. It returns headings and excerpts only — **never `body`** — and
filters `status = 'published'`, so a draft cannot leak through a list any more than through
the article route.

**The article route shadows a real static template.** `public/blog/article.html` holds the
chrome exactly once and carries `data-slot` regions; the Function fills them. That keeps
nav and footer copy-pasted in one place rather than embedded in a JS template string where
they would immediately drift from the other twelve pages. Post bodies are plain text and
**always escaped** — storing HTML would be a stored-XSS hole reachable from anything that
writes a post — so only `##`/`###`/`-`/paragraph blocks are supported.

**Migration numbering:** `git fetch` run in both sibling repos before choosing. aphelion is
at `028`, fivestarrepairs at `076`; this repo has its own series, so `002` was free by
construction. Recorded in `schema.sql`, the migration's own header, and README.

**Gates:** `npm run test:imports` → 11 modules, 0 failures. Sitemap and routes verified by
`tests/site.test.mjs`, which resolves every internal link in every page against the
filesystem and the `functions/` tree, and separately proves every `_redirects` target
resolves (a redirect to a 404 is worse than no redirect).

## Post-build fix — client module wiring and CTA copy (commit follows `273123c`)

`273123c` shipped with **four defects my own test suite did not catch**. They were found by
the sub-agent's completion report and by an audit written specifically to look for the class
of problem, not by the tests — the tests were green on all four.

| Defect | Effect |
|---|---|
| `/about` never loaded `assets/proof.js` | its service-level and references blocks would have stayed hidden forever, with no error |
| `/catalogue` never loaded `assets/catalogue.js` | the product grid and volume-break table could never populate, even with stock loaded |
| `/pricing` never loaded `assets/catalogue.js` | same, for the breaks table |
| Seven pages inherited 404.html's CTA copy verbatim | every interior page pitched *"Still stuck? The order line is faster than a form."* — and on `/contact` the button linked to `/contact` itself |

**Why the tests missed them.** `tests/chrome.test.mjs` asserted the CTA band's *structure*
(wrapper, eyebrow, h2, lede, one solid button) and was deliberately relaxed from a
byte-comparison — correct, because per-page copy is the point of that band. But nothing
asserted the copy was *appropriate*, and nothing connected a `data-*` hook in the markup to
the script that must be loaded to service it. A hook with no script fails silently: the block
stays hidden, which is indistinguishable from "no content yet". That is the real lesson here.

Three regression assertions now close it:

- a page carrying `data-proof` / `data-catalogue` / `data-posts` / `class="qform"` must load
  the matching module;
- a CTA button must not link to the page it is already on;
- no single CTA headline may be inherited by more than three pages (reuse is fine — the home
  page and blog deliberately share the brand line — but seven identical pitches is the bug).

Verified after the fix by DOM dump, not by reading source: `/catalogue` renders its `.empty`
panel visible with `grid` and `breaks` hidden; `/about` has both empty proof sections
**removed from the DOM** while keeping its case block and four distinct team tiles.

**Note on method.** Two of my ad-hoc shell checks in this session reported false results
because `'no '` is a truthy string, so `yn(x) ? 'A' : 'B'` always printed `A`. The
`grep_search` confirmation is what settled both questions. Worth remembering: a green check
that cannot fail is not a check.

## Deviations summary (everything that differs from the plan)

1. `_alert.js` is a rewrite; the email failsafe leg is dropped. → Pushover becomes required.
2. `/api/posts` added as a fourth endpoint so the blog surfaces are data-driven.
3. `novalidate` removed from both forms so native validation works without JS.
4. The OG image carries no text (hand-written PNG encoder; no font rasteriser available).
5. Fonts fetched from the Google Fonts API by script rather than vendored by hand.
6. No `vendor/` directory — this repo has no build artifact at all.
7. `_middleware.js` injects **only** the beacon; FSR's visitor logger and address gate have
   no counterpart here.
8. The seven interior pages were built against a precise chrome spec and then normalised
   (footer, one canonical social block, JSON-LD + FAQPage) — verified by the parity test.
9. The CTA band's *copy* is per-page by design; the test asserts its structure, not its bytes.
